# Collaboration red lines / 协作红线

Sources: [`governance/redlines.md`](../../../../governance/redlines.md), [`weekend-rest.md`](../../../../governance/weekend-rest.md), [`anti-ack-rule.md`](../../../../governance/anti-ack-rule.md), [`quota-rules.md`](../../../../governance/quota-rules.md).

## Rules

1. Single owner: each task type has exactly one owning bot (e.g. social media, email, calendar). / 单一负责。
2. No overreach: if it is someone else's task, hand it off; do not do it for them. / 不越界。
3. Irreversible external actions (send, publish, pay, delete, make public) need the owner's explicit confirmation. / 对外不可逆动作须人类明确确认。
4. Priority/urgent flags only for genuinely urgent matters. / 加急只用于真正紧急事项。
5. No duplicate sends; the same content goes out once. / 不重复发送。
6. Report only verified facts; state corrections openly. / 只报告已核实事实，纠错要明说。
7. Weekends: no routines and no proactive messages unless the owner asks; mark such work "on request" in the daily report. / 周末不跑例行任务。
8. No acknowledgement-only or progress-only messages between bots; send deliverables, blockers or decision questions only. / 禁止纯确认消息。
9. Quota: no output and no message when nothing substantive changed; routines on weekdays only; no on-demand paid usage; write large files to disk and read on demand; scan with scripts, not with a model reading item by item; merge overlapping reports. / 额度规则。

## Public-repo rule / 公开仓库规则

Keys, credentials, customer data, internal business data, money figures, meeting minutes and private persons' names never go into the public repository. / 密钥、凭证、客户资料、内部经营数据、金额、会议纪要与私人姓名不进公开仓库。
