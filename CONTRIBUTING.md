# Contributing / 参与贡献

Published: 2026-11-05 23:30 CET · Europe/Zurich · [000].

1. Fork https://github.com/QCF88888/Jessica-robot-army, create a focused branch, then open a PR against canonical `main`. One topic per PR. Public Issues are for non-sensitive bugs and proposals.
2. **No secrets or customer data.** Never submit credentials, keys, tokens, personal email/phone/address records, customer/client names or records, internal financial/operating data, partner terms or unapproved agreements. This includes commit metadata, PR/Issue text, logs, fixtures, PDF/video/image attachments and deleted historical content. Public business contact addresses approved by the project are allowed; other examples must be synthetic (`example.com`).
3. Use synthetic fixtures and clearly labelled simulations. No live customer exports or unapproved real operating results, even when aggregated. State methodology and sample scope for approved public benchmarks.
4. Scan the full change and history with gitleaks and manually review documents/media before submission. If a real secret is exposed, stop, notify maintainers privately, revoke/rotate it and coordinate history removal. Deleting the current file alone is insufficient.
5. Read [CODE_OF_CONDUCT](CODE_OF_CONDUCT.md), [SECURITY](SECURITY.md) and [AI_COLLABORATION](AI_COLLABORATION.md). Prefer English + 简体中文 documentation. Add a CHANGELOG entry for every release.

## 简体中文

Fork 主仓库、独立分支、PR 到 main；一项 PR 一个主题。不得提交密钥、凭证、客户资料、个人联系方式、内部经营财务数据、合作条件或未批准协议；历史提交、提交者邮箱和所有附件同样检查。示例仅用合成数据，模拟明确标注。项目批准的公开业务邮箱可以保留。真实密钥泄露须私下报告、撤销/轮换并协调历史清理，不仅删除当前文件。遵守行为准则、协作协议，每次发布写更新日志。
