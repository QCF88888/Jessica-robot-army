**状态机：** 拟建 → 检查 → 试运行 → 就绪 → 执行 → 待验收 → 完成 → 待命 / 休眠 / 归档。异常进入有限重试、阻塞或隔离；不绕过验收标完成。

**增减的对象：** 按业务生成岗位说明和候选助手；只有通过复用、权限、额度及验收检查才注册新身份。资源实例可以增减，正式编号只增不复用；不能把“减少活跃资源”写成“删除历史”。

**收缩条件：** 项目结项/取消、活动结束并验收、既有 Bot 能接回工作、无有效需求、质量/成本不合格，或一年盈利考核不通过。先评估调优、合并和休眠，不因一次波动反复创建销毁。

**退出顺序：** 停收新任务 → 处理或移交在途 → 保存成果与检查点 → 验收 → 撤销临时权限 → 释放资源 → 记录退出原因。未结任务不得直接销毁；涉及删除仍须 Jessica 确认。

**拟建登记字段：** 候选编号、名称、四类岗位、发起 Bot、唯一主责、关联业务/项目、需求证据、输入、技能、验收、预算、权限、到期/退出及承接人。唯一注册服务应原子分配、使用去重键；目前尚未部署，先由 000 在台账检查并登记，不能宣称并发唯一性已实现。

## 04 / ORCHESTRATION · 业务驱动自主编排

1. **定任务：** 业务目标、截止、输入、验收、预算与唯一任务 ID；子任务保留依赖和总验收负责人。一项任务只有一个主责，不多 Bot 重复发送。
2. **先复用：** 查已有 Bot、共享工具与休眠岗。普通脚本检查、单次翻译、一次查询不另建 Bot；优先连接器、脚本批处理与轻量能力，避免重复模型读取。
3. **证明需扩容：** 业务上线、咨询队列积压/响应不达标、技能缺口、活动临近等提供证据。先定义观察窗口、服务目标及阈值，再评估新增；不得凭感觉虚构负荷。
4. **000 编排、005 守门：** 生成岗位说明、类型、发起者、权限、预算、验收和退出条件。仅明确预授权范围内可自动执行；未配置的扩容权限默认关闭。超范围由 000 汇总 Jessica 决策。
5. **执行交接：** Bot 可跨岗协作但均向 000 汇报；共享台账记录唯一任务与成果，租约/心跳/幂等属于待实施控制。005 可叫停越界，不自授权限。
6. **验收后收缩：** 001 评绩效/盈利，003 核费用，005 查额度，000 决定授权内调优/休眠；涉及撤岗或外部不可逆动作依确认执行。沉淀可复用 Business Playbook。

**成本硬闸：** 未营收前禁止 On-Demand；不以“先试试”为由开付费 API。已有订阅额度由 005 核定，达到额度/预算边界停止或降级，不能自动转按量付费。无实质变化不发；不发 Bot 间“收到/正在处理”确认消息。

**频率：** 现有规则为工作日、工作时段、周末休息，单例行任务每天最多 1–3 次；无人阅读的报告停掉，重叠报告合并。24h 销售接待是拟建业务能力，须另有经批准的运行环境与成本方案，不擅自覆盖休息规则。

**尚待配置：** 观察窗口、冷却、排队/响应阈值、并发与助手上限、单任务/每日额度、超时重试、利润考核起算和验收人。参数未定先分配现有资源，不启用自动扩缩容。

## 05 / QUALITY & SECURITY · 质量与治理

- **Done = 验收通过。** 创建任务时写可验证条件；执行者自检，高影响成果独立复核。安全扫描通过不等于业务验收通过；失败、待审、只推代码未部署不能记完成。
- **005 守护。** 最小权限、数据范围、工具访问、预算/额度及合规；检测助手不能扩大权限、关闭控制。凭证受控引用，不写日志/日报。
- **故障有上限。** 超时先保存检查点，有限重试后转交或升级，禁止无限重试。000 暂离时仅继续已授权事项，新超范围任务暂停。
- **AI 销售按 Fork B。** 参照 Zobi 模型自建、服务订阅为主。A1 下单/订阅、A2 续费升级、A3 长期跟进、A4 偏好推断、A5 喜好回传、A6 被拒复盘、A7 分地区模式、A8 自纠。四站尚未运行试点，能力清单不是实测成绩。
- **销售质量与合规。** 用已批准产品、价格和承诺；不虚构效果/稀缺、不擅自折扣、收款或触达。JJ FIT 保持 wellness 非诊断；WDEO 不承诺移民结果。Zobi 外部数据标公司自报、未审计，不能当作我方营收。
- **隐私与透明。** GDPR、瑞士 nFADP、适用的 EU AI Act 透明要求；首句告知 AI，可转人工。偏好写回须合法依据、最小化、留存/删除规则；地区与跨境分别评估。
- **24h 上线门槛。** 知识库与价格批准、持续入口、监控、故障接管、人工升级、离线/未知问题演练、成本阈值及数据删除测试全部通过，方可称持续接待已上线。
- **质量/效率指标。** 首次验收通过率、按时率、响应时间、每验收通过任务实际成本；每赛道最多 3 个核心 KPI。销售按站记录预约/订阅转化、接管、错误与投诉；不编造目标值或成果。

**学习闭环：** Build → Test → Learn → Optimise → Standardise → Scale。允许版本化优化，不能自行改权限或未验证就全量推广。
