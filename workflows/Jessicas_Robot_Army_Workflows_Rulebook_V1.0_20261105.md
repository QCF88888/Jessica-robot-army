## 01 / MISSION · 核心定位

**核心价值：** 高效 · 快捷 · 质量 · 低成本。质量达到验收标准、时效满足要求，在此基础上尽量减少耗时与成本。

**系统定位：** 以 **000 MM** 为总统筹，核心机器人与动态助手直接协作。根据任务需求自主编排、增减与汇报，沉淀可复用的 AI Business Playbooks。

**演示边界：** 配套视频为**系统行为模拟**，展示编号、助手生成、任务交接、验收、释放与日报。画面中的任务和状态**不是**已部署系统的实时运行证据。

**设计原则：**
- 保留正式岗位编号
- 优先复用而非重复创建
- 协作不强制经过 MM 中转
- 安全与质量门槛不因成本压力降低
- 全过程可追溯

## 03 / LIFECYCLE · 四类岗位

| 类型 | 规则 |
|------|------|
| **终身岗** | 长期保留身份、职责和记忆；无任务时待命或休眠。自动调度可暂停运行资源，但不得擅自删除永久岗位身份或核心记忆。 |
| **项目岗** | 关联项目 ID、阶段目标与验收标准；结项、成果移交和验收完成后归档。 |
| **临时岗** | 单项任务或短期高峰；必须设范围、到期条件与预算；验收后释放资源，成果与必要记录保留。 |
| **工具岗** | 封装检索、检测、翻译等专项能力；可被多 Bot 共享。逻辑身份稳定，调用实例短暂；**不因一次工具调用就新增编号**。 |

**状态流转：** 拟建 → 检查 → 试运行 → 就绪 → 执行 → 待验收 → 完成 → 待命 / 休眠 / 归档。异常进入重试、阻塞或隔离，**不绕过验收直接标记完成**。

**退出条件：** 停收新任务 → 处理或转交在途任务 → 保存交付与检查点 → 撤销临时访问权 → 释放资源 → 记录退出原因。有未结任务时不能直接销毁实例。

## 04 / ORCHESTRATION · 自主编排

1. **明确任务** — 目标、发起者、截止、技能、输入、验收、预算；唯一任务 ID；子任务保留依赖与总验收负责人。  
2. **判断需求** — 排队、耗时、技能缺口、服务时段、失败情况；先查已有 Bot / 共享工具 / 休眠岗。  
3. **选择执行者** — 权限、技能、质量、时限为硬条件；合格者中选成本与耗时更优；简单任务用轻量能力。  
4. **扩容检查** — 确需新增时生成岗位说明、类型、发起 Bot、预算、退出条件与验收方法。**005** 查权限与安全；预授权内自动执行，超预算/权限交 **000** 汇总 Jessica 决策。  
5. **执行与交接** — Bot 可直接跨岗协作；共享任务台账为事实依据；租约、心跳、幂等键防重复；依赖未完成不得误报完成。  
6. **评估与收缩** — 按质量、时效、成本决定保留 / 调优 / 休眠 / 释放；设观察窗口与冷却，避免瞬时抖动反复创建销毁。

**待配置参数：** 工作时段、超时、观察窗口、并发上限、助手数量上限、单任务及每日预算、重试次数。**未配置的扩容权限默认不启用**；优先分配已有资源。

## 05 / QUALITY & SECURITY

- **质量验收：** 创建时定义可核验通过条件；执行 Bot 自检；高影响交付由独立验收角色复核。安全检测通过 ≠ 业务质量验收通过。  
- **005 治理：** 最小权限、数据范围、工具访问、成本异常、越界行为。安全助手可检测报告，**不能自行扩大权限或关闭控制**。凭证受控引用，不写任务日志和日报。  
- **运行故障：** 超时先存检查点；有限次重试后转交/升级；禁止无限重试。MM 暂时不可用时，已授权任务继续；新超范围任务暂停。  
- **24 小时服务：** AI 销售岗需持续运行环境、监控、故障接管与人工升级入口。无咨询时可事件驱动待命，接待入口须可用。  
- **销售边界：** 仅用批准的产品资料、价格与承诺；不得编造健康效果、擅自折扣或收款。  
- **效率衡量：** 首次验收通过率、按时完成率、响应时间、每验收通过任务实际成本；估算与实测分开。  
- **学习闭环：** Build → Test → Learn → Optimise → Standardise → Scale。优化可版本化；不自行改权限边界或未验证就全量推广。

## 06 / VISUAL SYSTEM · 可视化工作台

- **布局：** 000 MM 固定左上；000–019 核心网络；动态助手在发起 Bot 附近或助手区。连线=协作，**不暗示所有任务必须经 MM**。  
- **节点字段：** 编号、名称、类型、状态、任务量、负荷、耗时、成本；点击展开任务/权限/项目/助手/交付证据；未接入数据明确标记。  
- **连线语义：** 虚线=拟建/配置/试运行；有向实线=任务或成果交接；双向=协作；盾牌=安全检查；灰色=待命/休眠/归档。配文字标签，不仅靠颜色。  
- **演示场景：** 001→020 项目执行助手（临时）；005→021 安全检测助手（工具）；006→022 WDEO 营销官（项目）；007→023 JJ FIT AI 销售官（终身，示例）。  
- **收缩：** 020 验收后释放；021 检测后待命共享；022 结项归档；023 保留长期身份与服务入口。编号持续累计，活跃数可升可降。  
- **控制台：** 核心岗数、动态助手数、运行/待命、质量、时效、实际成本、异常。真实接入前仅展示标记明确的演示状态，**不用虚构营收或运行成绩**。

## 07 / DAILY REPORT · 000 MM 每日总报告

**汇报路径：** 各 Bot/助手写共享台账；000 按 Europe/Zurich 自然日汇总交 Jessica。发送时间/渠道/收件对象尚待配置；**本手册不自动创建定时发送**。

**日报内容：**  
① 完成与未完成任务及交付链接  
② 新增/休眠/退出编号与原因  
③ 任务量、负荷与跨 Bot 交接  
④ 24h 服务在线、响应与未解决咨询  
⑤ 耗时、实际成本、失败与重试  
⑥ 005 安全结果与处置  
⑦ 次日安排及待 Jessica 决策事项  

**统计口径：** 完成以验收通过为准；任务 ID / 交付 ID 去重；跨 Bot 协作记贡献但集团成果只计一次；核心岗数、累计注册数、当前运行数分别展示。

**数据诚实：** 未接入写「未接入」；无证据写「暂无数据」；实测为零才写 0。重大异常及时升级，不等日报。

**最小台账字段：** Bot ID、岗位类型、发起 Bot、项目 ID、任务 ID、输入、验收标准、状态、交接对象、起止时间、实际成本及币种、交付链接、验收人、错误与重试、退出原因。

**执行手册沉淀：** 任务目标、参与 Bot、步骤、耗时、成本、交付、问题、优化后标准流程。000 汇总，001 评估绩效，005 检查治理边界。

## 08 / ACCEPTANCE · 实施与验收

> 规则确认 ≠ 系统已经部署。

| 阶段 | 内容 |
|------|------|
| 1 名册与台账 | 核对 000–019；唯一编号服务与四类岗位字段；任务 ID、事件、交付与验收证据。每个核心岗类型须逐项指定，不能从名称猜测。 |
| 2 调度与守护 | 队列、预算、权限、状态机、有限重试、安全隔离；先用模拟任务验证去重/扩缩容/故障恢复。 |
| 3 工作台与日报 | 真实事件接入；统计口径；000 日报覆盖核心 Bot 与全部助手，协作成果不重复计数。 |
| 4 24 小时岗位 | 选 JJ FIT AI 销售试点；批准知识库与人工接管；验证异常/离线/未知问题/响应/预算后再扩大。 |

**必须通过的演练：** 重复创建只分配一个身份；超预算不能扩容；助手不自授权限；MM 离线时已授权任务继续；交接可追溯；失败不算完成；退出前转交在途；日报与台账一致。

**交付说明：** 本手册与配套演示共同作为实现与验收依据。演示使用正式核心名册与拟新增助手；**未修改在线生产系统，也未启动自动扩容或定时日报**。
